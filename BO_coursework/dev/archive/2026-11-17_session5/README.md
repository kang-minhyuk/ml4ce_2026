# Final algorithms

| file | track | what it assumes |
|---|---|---|
| `informed_bayes2.py` | informed (highest score, session 4) | Everything in `informed_bayes.py`, plus a 300-number table of the library members' plate titers (pre-computed with the simulator): the library is weighted by how close a member's plate titer is to the clone's, which sets each clone's first Pilot glutamine recipe; unaffordable plates carry to the next budget segment; two MBR batches before the first Pilot. off_big 0.745 vs 0.730, every split better. |
| `informed_bayes.py` | informed + Bayesian T/pH decisions | Everything in `informed_library.py`, plus a fixed temperature/pH response template from an offline simulator study (`TMPL_W`). Each clone's operating T/pH is the Bayes action under a grid posterior over its optimum; later plate conditions maximise the expected value of information about those decisions; clones are ranked by posterior-mean plate height and screened in order of height plus expected relative titer. |
| `informed_library.py` | informed + transfer-BO library | Everything in `informed_funnel.py`, plus an embedded, compressed library of simulated Pilot glutamine-response surfaces (300 simulated clones, 7×6×4 absolute glutamine grid, 12 principal components; ~87 KB file). From the incumbent's 3rd Pilot run, its titers re-weight the library members and the next glutamine recipe maximises the mixture's expected improvement. |
| `informed_funnel.py` | informed (compact) | Structural priors from studying the simulator family, all relative to `lab.bounds`: glucose at its upper bound in every feed; glutamine searched on a log scale; a 3-recipe glutamine portfolio; temperature/pH constant over the run and equal to each clone's growth optimum. |
| `generic_bayes.py` | generic (highest generic score) | `generic_funnel.py` plus the Bayes T/pH decision, value-of-information plates and expected-titer screening order, with T/pH widths learned in-run from the plates (no simulator-derived widths). +0.027 to +0.051 over `generic_funnel.py` on every split. |
| `generic_funnel.py` | generic | Same machinery (plates → MBR screen → Pilot racing + GP/EI), but no recipe knowledge: prior recipe at the centre of the search box (glutamine at the centre of a log range), glucose searched, plates at mid-range medium. |

`informed_bayes.py` beats `informed_library.py` on every split with an oracle (+0.056 to +0.107; +0.091 ± 0.008 on
400 fresh official-style scenarios) and runs faster (median ~5 s). `informed_library.py` scores higher than `informed_funnel.py` by +0.004 to +0.011 of oracle on every split and is never
worse. The trade-off is a large table of pre-computed numbers in the file. It contains no clone names, nothing read
from the lab or from files, and no lab settings. Choose `informed_funnel.py` if you would rather not submit that table.

All six:
- only import numpy, scipy and sobol_seq;
- only use the public `lab` API and read every setting from `lab`;
- pass `check_my_algorithm` once `STUDENT_NAMES` is filled in.

To submit one, copy it into `student/algorithms/my_algorithm.py` through the notebook's `%%writefile` cell and set
`STUDENT_NAMES`. The library tables are regenerated by `dev/embed_lib.py` from `dev/gln_lib.npz`, which
`dev/lib_gen.py` produces.
